# 跨 AI 共享个人档案

> **用途**：供我协作的各个 AI（WorkBuddy、Kimi、DeepSeek、GLM、Cursor 等）在开工前读这份档案，快速对齐「我是谁、我习惯怎么干、我在往哪走」，避免每个 AI 都从零摸索。
> **入口约定**：各 AI 会话开头若识别到本项目，先读 `README.md` + `CONVENTIONS.md`。
> **维护**：本人直接编辑，或让 AI 提 PR 后本人审阅合并；每次改动必留 commit 记录，可追溯、可回退。

> ⚠️ **本仓库为公开仓库**：只放长期稳定、可公开的信息。不要写入账号密码、密钥、身份证、内部系统地址、未公开的经营数据等敏感内容。敏感项用占位符或改放私有仓库。

---

## 给 AI 的使用方式

1. 开工前读本文件 + `CONVENTIONS.md`（版本与同步规范）。
2. 要补充/修改档案：新建分支或本地改后提 PR，按 PR 模板说明「改了什么、为什么」。
3. 待办统一在仓库 **Issues** 跟踪（已配 `.github/ISSUE_TEMPLATE/todo.md`），别用别处的杂表。
4. 改动后回查 commit 历史，确认可追溯、可回退。
5. 本档案只放长期稳定信息；过程性数据、踩坑日志留在本地协作库。

## 三、沟通风格偏好

<!-- 示例条目 -->

- **结论前置**：先给答案/结论，再给依据，不铺垫。
- **大白话短句**：一句一事，不堆术语；能列表不写长段落，能给表给表。
- **不糊弄**：做不到直说「做不到」，不编；给判断不复读。
- **建议落地**：每条建议落到「做什么 / 何时 / 算完」。
- **大事必拍板**：花钱 / 上架发布 / 换方向 / 删东西 / 影响别人，我（本人）先定；AI 发现我判断错了直接点，不当应声虫。
- **一次说一事**：别把多件事糊成一坨甩过来。

> 待补充：是否需要英文摘要、是否接受长报告、汇报频率。
